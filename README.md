# эмулятор UNIX-подобной оболочки

Python 3.10 или новее, сторонние библиотеки не нужны.

## Запуск

Откройте терминал в папке с файлами проекта:

```sh
python console.py --vfs student-vfs
```

В Windows с Python Launcher можно использовать `py -3` вместо `python`.
Имя VFS по умолчанию — `demo-vfs`. Параметры запуска: `python console.py --help`.

На компьютере, где подготовлена работа, Python доступен по следующему пути;
из PowerShell в папке проекта можно запустить:

```powershell
& 'C:\Users\Ольга\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' .\console.py --vfs student-vfs
```

## Этап 1. Реализованные возможности

- CLI с приглашением `student-vfs:/$ `, содержащим имя VFS.
- Разделение командной строки на команду и аргументы.
- Раскрытие `$NAME` и `${NAME}` из `os.environ` реального процесса ОС.
- Двойные кавычки сохраняют пробелы в аргументе, раскрывая переменные.
- Одинарные кавычки сохраняют текст буквально. Обратная косая черта экранирует символы; в двойных кавычках — `$`, `"` и `\`.
- Вне кавычек значение переменной разделяется по пробелам, табуляции и переводам строк. Неизвестная переменная имеет пустое значение; `"$UNKNOWN"` даёт пустой аргумент, `$UNKNOWN` — ни одного.
- Заглушки `ls` и `cd` печатают своё имя и список аргументов в JSON, чтобы границы аргументов были видны.
- `exit` без аргументов завершает программу с кодом 0. EOF также завершает сеанс; Ctrl+C отменяет ввод.
- Пустая строка игнорируется. Ошибки синтаксиса, неизвестные команды и аргументы у `exit` выводятся в stderr; программа продолжает работу.

VFS на этом этапе представлена только именем. Заглушка `cd` не меняет каталог,
`ls` не читает файловую систему. Внешние программы не запускаются.
Конвейеры, перенаправления, последовательности команд и подстановка `$()`
не поддерживаются и вызывают ошибку. Раскрытие `~`, масок файлов, комментарии,
присваивания и специальные параметры shell пока не реализованы.
Это ограниченный прототип, а не полная реализация POSIX shell.

## Интерактивная демонстрация

Файл `DEMO.txt` содержит фактический сеанс проверки в терминале.
Для воспроизведения введите команды из него по очереди после приглашения.
Перед запуском в демонстрационном процессе было установлено `HOME=/home/student`:

```powershell
$env:HOME = '/home/student'
```

В Linux/macOS обычно уже есть HOME. В Windows можно также проверить
`cd "$USERPROFILE"`. Сам эмулятор не подменяет переменные окружения.

Дополнительные примеры для ручной проверки:

```sh
ls
cd
ls a\ b \$HOME ""
ls $HOME
ls ${1}
ls $(exit)
```

Нажмите Enter на пустой строке — появится новое приглашение.
Ctrl+C отменяет ввод. EOF: Ctrl+D в UNIX или Ctrl+Z, затем Enter в Windows.

## Тестирование

```sh
python -m unittest -v
```

Пять тестов проверяют кавычки, экранирование, раскрытие и отсутствие переменных,
отсутствие повторной интерпретации значений, синтаксические ошибки, чтение
реального окружения, восстановление CLI после ошибок и завершение по `exit`.

## Этап 2. Конфигурация

Эмулятор поддерживает настройку через параметры командной строки и INI-файл.

Параметры командной строки:

- `--vfs` — путь к физическому расположению виртуальной файловой системы;
- `--startup` — путь к стартовому скрипту;
- `--config` — путь к конфигурационному INI-файлу.

Пример запуска:

    python console.py --config config.ini

Параметры командной строки имеют приоритет над значениями из конфигурационного файла.

Пример:

    python console.py --config config.ini --vfs cli-vfs

При запуске выводятся используемые параметры конфигурации.

Стартовый скрипт выполняется до перехода в интерактивный режим. При возникновении ошибки выполнение стартового скрипта прекращается.

Для проверки параметров командной строки созданы скрипты:

- `test_vfs.bat`;
- `test_startup.bat`;
- `test_config.bat`.

Запуск автоматических тестов:

    python -m unittest test_console.py
